# 应用生命周期

运行时取得共享 TTY 和四页堆，创建 `/hello.txt` 后执行独立 Kilo 或 Launcher。Launcher 按用户选择调用静态链接的入口。应用使用同一 CR3、TTY 授权、堆和 RAM FS。文件信息是内置应用，文件查看来自 sbase。

进入每个应用前记录 termios，并要求共享堆无活动对象。正常返回验证堆与文件描述符无残留。Kilo 可诊断的 OOM 或 I/O 错误通过同一用户栈上的受控返回点结束该次调用。应用边界清理剩余文件描述符，回收堆对象并恢复终端。清理失败会终止会话。Launcher 持有的 RAM 文件对象继续有效。普通域故障和内核强制撤销仍由 Liberums 处理。

Kilo 的读入使用 128 字节扫描缓冲，然后把数据读入最终行对象。无 Tab 的行直接使用行文本渲染，保存按行流式写入。保存前检查完整尺寸，超出 RAM 文件容量时保留已保存内容。会话回读以文件长度和 FNV-1a 校验值检查；集成测试仍逐字节核对数据。

退出画面在 VGA 授权仍有效时完成。之后释放设备与普通 RAM，并在 COM1 报告结果和退出状态。
